# LWOM 轻量工单管理平台 数据库设计

数据库一共四张表：用户表、工单表、操作记录表、附件表。
配套的建表脚本在同一个文件夹里的 建表.sql。

---

## 一、数据表文档

### 第一张：用户表
存所有能登录系统的人。

| 字段 | 存什么 | 规则 |
|------|--------|------|
| 编号 | 系统内部序号 | 不显示给用户，别的表靠它找到这个人 |
| 用户名 | 登录用的名字 | 不能重复 |
| 密码 | 登录口令 | 加密后存放，不留原样 |
| 姓名 | 真实姓名 | 界面上展示用 |
| 角色 | 管理员、运维、普通用户 | 三种里选一个 |
| 状态 | 正常、已禁用 | 禁用后不能登录 |
| 创建时间 | 建账号的时间 | 系统自动填写 |

### 第二张：工单表
存每一张工单。

| 字段 | 存什么 | 规则 |
|------|--------|------|
| 编号 | 系统内部序号 | 不显示给用户 |
| 工单编号 | 界面上看到的编号 | 自动生成，例如 20261008-001，当天第几张就排到几 |
| 工单标题 | 一句话概况 | 提交时必填 |
| 工单类型 | 保修、咨询、其它 | 三选一 |
| 优先级 | 高、中、低 | 三选一 |
| 问题描述 | 详细说明 | 提交时必填 |
| 状态 | 新建、处理中、待确认、已关闭 | 只能按约定好的流程变化 |
| 提交人 | 提交这张工单的人 | 记的是用户表里的编号 |
| 处理人 | 当前负责处理的人 | 可以为空，还没分配时就是空 |
| 创建时间 | 提交时间 | 系统自动填写 |
| 更新时间 | 最近一次变动的时间 | 系统自动更新 |

### 第三张：操作记录表
每发生一个动作就记一笔，谁在什么时候做了什么。

| 字段 | 存什么 | 规则 |
|------|--------|------|
| 编号 | 系统内部序号 | 不显示给用户 |
| 所属工单 | 这条记录属于哪张工单 | 记的是工单表里的编号 |
| 操作人 | 谁做了这个动作 | 记的是用户表里的编号 |
| 操作类型 | 提交、分配、改派、处理完成、直接关闭、确认关闭、退回、添加备注 | 八种里选一个 |
| 操作内容 | 具体说明文字 | 比如备注写了什么、改派从谁改给了谁 |
| 操作时间 | 动作发生的时间 | 系统自动填写 |

这张表有个铁规矩：只增不改不删，历史记录谁都不能动。

### 第四张：附件表
记录每个工单上传过哪些文件。

| 字段 | 存什么 | 规则 |
|------|--------|------|
| 编号 | 系统内部序号 | 不显示给用户 |
| 所属工单 | 这个文件挂在哪张工单上 | 记的是工单表里的编号 |
| 文件名 | 上传时的原始文件名 | 下载时按这个名字给回用户 |
| 存放位置 | 文件在服务器上实际存放的路径 | 下载时按这个去找文件 |
| 文件大小 | 文件占多少空间 | 用来看有没有超过 5 兆限制 |
| 上传人 | 谁传的 | 记的是用户表里的编号 |
| 上传时间 | 传上来的时间 | 系统自动填写 |

## 二、表与表的关系图

四张表之间的关系一共就六条，箭头表示「一个对应多个」：

用户表
├─ 一个用户可以提交多张工单 ──→ 工单表
├─ 一个用户可以被指派处理多张工单 ──→ 工单表
├─ 一个用户会产生多条操作记录 ──→ 操作记录表
└─ 一个用户可以上传多个附件 ──→ 附件表

工单表
├─ 一张工单会产生多条操作记录 ──→ 操作记录表
└─ 一张工单可以挂多个附件 ──→ 附件表

看的时候反过来理解就行：每条操作记录、每个附件，都只属于一张工单；每张工单也只有一个提交人。
